# GNU Base64 — Encoding and Decoding

Base64 represents binary data as printable text, using a 64-character alphabet and optional equals padding. Three bytes map to four six-bit symbols. It is reversible without a key, not encryption. Common uses include MIME, HTTP Basic authentication representation and data URLs. Base64URL uses a different alphabet.

## Official downloads and installation
- https://www.gnu.org/software/coreutils/
- https://ftp.gnu.org/gnu/coreutils/
- https://www.gnu.org/software/coreutils/manual/coreutils.html

Ubuntu WSL2: run base64 --version. If missing, sudo apt update then sudo apt install coreutils. On Windows use Ubuntu WSL2 rather than downloading an unverified executable. PowerShell's .NET alternative for trusted UTF-8 text is [Convert]::ToBase64String([Text.Encoding]::UTF8.GetBytes("Hello World")); reverse with [Text.Encoding]::UTF8.GetString([Convert]::FromBase64String("SGVsbG8gV29ybGQ=")).

## Commands and examples
~~~bash
printf '%s' 'Hello World' | base64
printf '%s' 'SGVsbG8gV29ybGQ=' | base64 -d
printf '%s' 'Cat' | base64 -w 0
~~~
Expected: SGVsbG8gV29ybGQ=, Hello World, Q2F0. Pipe connects output to input; printf avoids an implicit newline; -d decodes; -w 0 disables GNU output wrapping. A normal echo adds a newline (Hello with newline gives SGVsbG8K). For owned files: base64 input.bin > output.b64 and base64 -d output.b64 > restored.bin; redirection can overwrite files, so use unused paths. Compare original and restored data with cmp input.bin restored.bin.

## Troubleshooting and security
Invalid input: check alphabet, padding and variants, preserve original bytes, and do not silently discard characters. Decoded bytes may be binary; save to a separate file rather than printing unknown bytes to a terminal. Check locale/text encoding if Unicode appears unexpected. Appearance alone is not proof. UniTrack and ProTrack-MX must not use Base64 as protection for credentials, student records or QR authenticity. No learner installation or tool execution claimed.
