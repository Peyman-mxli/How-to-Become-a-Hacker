# Topology documentation, LLDP and packet visibility

A physical diagram records links, ports and device placement; a logical diagram records subnets, VLANs, routes and trust boundaries. Maintain device purpose, owner, interface, media, uplinks, power dependencies, management access, redundancy, expected traffic and date of verification. Do not publish real confidential topology or student records. LLDP (Link Layer Discovery Protocol) advertises local neighbor information; it does not automatically map the full network. Authorized switch inventories and management data help validate diagrams.

Wireshark is a free/open-source packet analyzer. A capture interface receives visible traffic; protocol dissectors interpret headers and fields. On a switched LAN normal endpoints do not see all other unicast traffic. Authorized mirror ports, capture locations and permissions determine visibility; encryption limits payload visibility. [Official download](https://www.wireshark.org/download.html), [user guide](https://www.wireshark.org/docs/wsug_html/), [CLI reference](https://www.wireshark.org/docs/man-pages/wireshark).

Windows: download official installer, verify publisher, install Npcap if required for authorized live capture; use existing approved capture files without live capture. Ubuntu optional: sudo apt update; sudo apt install wireshark tshark; configure capture permissions per distribution documentation, not by running GUI as root. WSL2 sees its own virtual interfaces. tshark -D lists visible capture interfaces; tshark -r sample.pcapng -Y lldp reads an existing authorized file and displays LLDP frames; -r selects file and -Y specifies display filter. No capture file supplied; no capture or commands performed. Illustrative observation: LLDP system name and port ID may identify directly connected device. Absence may mean disabled LLDP or unsuitable capture vantage point.

Original documentation: campus access switch uplink to core, two scanner ports, management VLAN, approved API path; record which components share power or cable conduits. For UniTrack correlate network path issues with access-control API logs; for ProTrack-MX distinguish connectivity from cloud application auth. No additional lab required.
