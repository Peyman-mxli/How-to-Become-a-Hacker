# SOCKS and OpenSSH

SOCKS5 (RFC 1928) relays connections with authentication negotiation and requested destination. TCP CONNECT and UDP association are supported by compatible implementations. TCP 1080 conventional, configurable. SOCKS does not automatically encrypt payloads; DNS resolution depends on client configuration. OpenSSH provides secure authenticated remote administration and optional forwarding. SSH channel encryption is distinct from proxy or application encryption.

[SOCKS RFC](https://www.rfc-editor.org/rfc/rfc1928), [OpenSSH](https://www.openssh.com/), [SSH architecture](https://www.rfc-editor.org/rfc/rfc4251), [Microsoft OpenSSH](https://learn.microsoft.com/en-us/windows-server/administration/openssh/openssh_install_firstuse). Windows optional OpenSSH Client via Windows Optional Features; Ubuntu sudo apt install openssh-client if absent. ssh -V displays client version. No new installation required. For legitimate administration use approved accounts, host-key verification, least privilege and documented connection routes. An encrypted relay is not permission to access arbitrary resources. Unauthorized forwarding on compromised endpoints can weaken visibility; defenders review server forwarding policy, authorized listeners, process/network events and approved egress. Example: compare authorized remote-admin record to unexpected connection logs rather than create a hidden relay. Troubleshoot authentication, host-key mismatch and approved service reachability; never ignore host-key warnings.
