# Chisel — tunnel architecture and defensive reference

Chisel is a free/open-source TCP/UDP tunneling tool using HTTP transport and SSH for protection. Client/server roles mediate traffic; tunneling is distinct from HTTP message inspection. Approved remote connectivity is a legitimate use; unexpected relay processes or listeners can create security risk. [Official source and documentation](https://github.com/jpillora/chisel), [releases](https://github.com/jpillora/chisel/releases).

Optional reference: select official release matching Windows/Linux architecture, verify available checksum/signature, extract in isolated authorized workstation. chisel --help displays supported options without establishing connections; on Windows use .\chisel.exe --help if in current folder. Do not run remote installation scripts blindly. No relay deployment is required. Example defensive inventory: compare executable hash, publisher/source, parent process, assigned owner and approved network endpoints with policy; investigate unknown listeners and outbound sessions. Encrypted transport limits payload inspection but endpoint and connection metadata remain available. Restrict unmanaged tunnel tooling, use approved egress/remote access, monitor process events, investigate unauthorized connections. Troubleshoot incompatible binary architecture or missing executable path; actual network deployment requires separate authorization. No install or test.
