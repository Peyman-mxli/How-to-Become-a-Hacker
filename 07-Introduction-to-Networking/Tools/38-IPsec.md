# IPsec — IP-layer security architecture

IPsec protects IP packets according to security policy and security associations (SAs). ESP protocol 50 provides selected confidentiality/integrity and anti-replay; AH protocol 51 integrity/authentication without encryption. IKEv2 negotiates keys and SAs, commonly UDP 500; NAT traversal commonly UDP 4500. Transport mode protects upper-layer content with original IP header (AH and ESP coverage differ); tunnel mode encapsulates inner IP packet in new outer IP header. ESP protection depends on algorithm/configuration. SPD = Security Policy Database; SAD = Security Association Database. SAs are directional. IPsec differs from TLS, which protects a transport/application channel, and OpenVPN, which is a different VPN technology.

Original example: office A 192.168.10.0/24 to office B 192.168.20.0/24 with approved gateways and nonoverlapping subnets. Use authenticated peer identities, strong current cryptography, secure key storage, least privilege traffic selectors and logging. Avoid unreviewed production route changes. No tunnel deployment today.

Free/open-source strongSwan [official downloads](https://www.strongswan.org/download.html), [docs](https://docs.strongswan.org/). On approved isolated Linux VM choose supported packages (e.g. strongswan and strongswan-swanctl depending on distro), consult version docs; install only when required. swanctl --version or ipsec --version where installed; sudo swanctl --list-sas reads existing SAs if daemon and permissions allow. Linux ip xfrm policy and ip xfrm state inspect policy/state; **state output may expose cryptographic key material**, never share or publish it; prefer policy and approved status output. Windows Get-NetIPsecMainModeSA and Get-NetIPsecQuickModeSA inspect existing SAs. WSL2 kernel and privileges may differ. Wireshark filters esp, ah, udp.port == 500 || udp.port == 4500 on authorized existing capture. Troubleshoot peer identity/certificates, proposal mismatch, selectors, route overlap, NAT traversal and MTU. UniTrack inter-campus VPN is conceptual; ProTrack-MX uses managed HTTPS and should not assume IPsec.
