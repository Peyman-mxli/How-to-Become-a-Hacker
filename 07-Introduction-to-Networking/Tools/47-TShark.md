# TShark — offline packet inspection
TShark is Wireshark's free/open-source terminal-oriented protocol analyzer. Official [downloads](https://www.wireshark.org/download.html), [manual](https://www.wireshark.org/docs/man-pages/tshark.html), [display filter reference](https://www.wireshark.org/docs/dfref/). Windows installer can include TShark; optional Ubuntu sudo apt install tshark if needed (do not grant unneeded live capture permissions). No installation today. Verify with tshark --version. Use existing authorized capture only:
```bash
tshark -r example.pcapng -Y arp -n
tshark -r example.pcapng -Y "arp.opcode == 2" -T fields -e frame.number -e arp.src.proto_ipv4 -e arp.src.hw_mac
```
example.pcapng placeholder; not supplied. -r reads file, -Y applies display filter, -n disables resolution, -T fields selects output format, -e field names. Example expected illustrative output from independent sample: 2 192.0.2.20 02:00:00:00:00:14. First field frame number, second sender IPv4, third sender MAC. No capture performed. ARP request opcode 1, reply 2; Ethernet destination ff:ff:ff:ff:ff:ff broadcast. 60-byte capture may omit Ethernet FCS from 64-byte minimum frame; capture settings differ. Filter arp.opcode == 1 or arp.opcode == 2; eth.dst == ff:ff:ff:ff:ff:ff. Distinguish display vs capture filter. Troubleshoot path, quoting, installed version and protocol dissection; use tshark -G fields for field registry if needed. On Windows, use installed executable path if not on PATH. Do not publish captures containing personal/institutional information. Defensive review: compare claimed mappings with approved inventory and switch/DHCP evidence, legitimate changes possible. UniTrack/ProTrack-MX troubleshooting only in authorized context. No live capture or command execution required.
